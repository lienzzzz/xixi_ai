# 真人感指标与黄金对话评测（P1c）

最后更新：2026-10-01

这份文档是「真人感」的可测部分：**提问率 / 回复长度分布 / 禁用模板出现率**三条指标，
加上 pack `xixi_v02_refactor_pack/tests/golden_conversations.md` 的 12 条黄金对话接入评测，
以及 V0.1 与 P1 的同口径对比。指标定义只有一份实现：
`scripts/lib/realism-metrics.ts`；跑一次语料、出一次报告的命令是 `scripts/eval-realism.ts`。

## 1. 一条可重跑命令

**改造前后的对比（同一批语料，读已捕获的转录，不花钱）**：

```powershell
node scripts/eval-realism.ts --replay docs/benchmarks/realism-2026-10-01-v01-vanilla.json   # 改造前（V0.1）
node scripts/eval-realism.ts --replay docs/benchmarks/realism-2026-10-01-v02-wip.json        # 改造后（P1 快照）
```

**现场重跑 / 其它开关**：

```powershell
# 黄金语料 + 仓库既有语料，真实 MiMo，跑 3 遍（样本小，必须看抖动），写报告
node scripts/eval-realism.ts --corpus=all --repeat=3 --label v02

# 不花钱且用当前修订的分段器补齐分段数据、重写报告
node scripts/eval-realism.ts --replay docs/benchmarks/realism-2026-10-01-v01-vanilla.json `
    --re-render --out docs/benchmarks

# 离线自检（只验证管线，指标结论不采信；**必须换 --out**，否则会往 docs/ 里写没人认领的报告）
node scripts/eval-realism.ts --fake --out "$env:TEMP\realism-selfcheck"
```

其它开关：`--gate` 默认开（黄金机械期望不满足就 exit 1）；`--no-gate` 只测量；
`--out <dir>` 换报告目录；`--corpus=golden|v01|all`；`--repeat=N`。

**跑完会写两个文件**（本次两份都在 `docs/benchmarks/`）：
`realism-<日期>-<label>.md`（人看的报告）与 `realism-<日期>-<label>.json`（机器复算的原始记录，
含逐轮原文与分段数据）。报告里带「最后更新」标记，满足 `npm run check:docs`。

## 2. 指标口径（先读，否则数字会被误读）

| 指标 | 定义（**唯一口径**，实现只有一份） | 备注 |
|---|---|---|
| **分母** | `action === 'SPEAK'` 且文本非空且**不是引擎修复句**（`UNBACKED_FACT_REPLY`）的**开口轮** | 沉默轮与修复句都不进分母——修复句是程序写的，算进分母等于拿程序的行为当模型的行为（t6 的 F2，t16 修） |
| **提问率（主口径）** | **末句以 `？/?` 收尾**的开口轮占比（末尾允许引号/括号） | **30–50% 的带内判定只看这一条** |
| 提问率（辅口径） | 回复里**含** `？/?` 的开口轮占比 | **仅供参考**，不作判定（旧口径正是这一条，会把 46% 读成 69%） |
| 口径带 | 30–50%（项目目标） | 超出只在报告里注明「偏高/偏低」，不单独判失败 |
| 回复长度分布 | 去空白字符数，四档：半句 ≤15 / 短句 16–40 / 中句 41–90 / 长解释 ≥91 | 按 `respond().text`（也就是交给分段的原文）计数 |
| 交付分段 | 每轮段数 + 单段字数（ADR-0010 的分段结果） | 「长解释是被拆成 8 个小段，还是塞成 1 个 341 字的巨段」，这一条才看得出来 |
| 禁用模板出现率 | 命中「AI 套话」词表的开口轮占比 | 词表 13 条，每条都写明为什么算套话；pack 的「不好」例子是它的回归夹具 |
| 沉默率 | 沉默轮 / 被接受的轮 | §55 的沉默是一等公民，不是失败 |
| 重复 6 字短语 | 同一 6 字窗口出现在 ≥3 轮 | 抓「换句话说的模板化收尾」（逐字比对漏掉的那类）；`--repeat>1` 时汇总值会被跨次重复污染，看逐次数 |
| 最长同结构连续轮 | 连续「同一长度档 + 同样有没有问号」的轮数 | pack §2.1 的「连续多轮同结构」 |
| pack §2.1 警报 | >80% 同一长度档 / >80% 带问题 / 出现「如果还有什么」式收尾 / 同结构 ≥3 轮 / >20% 轮出现超 60 字单段 | 报告出来给人看，不替代人工抽检 |

**数字怎么写**：一律「**均值 X%（n=N，极差 A–B）**」或「该次运行 Y%（a/b）」，**不要只写单次数字**——
单次 28 轮的极差实测可到 6–7 个百分点（t17 的 O1 与 t16 的复算都指向同一条）。

**长度与分段的关系（别误读）**：V0.1 的硬上限是「最多 3 段 × 每段 60 字」，
但**超出容量的尾巴会并进最后一段**（`packages/conversation/src/segments.ts` 的 M1 行为，
见 `tests/unit/core/reply-segments.test.ts` 的「than the tail merges into the last segment」），
所以「3×60=180」并不等于「用户最多听到 180 字」——实测最长单段 341 字。
P1 把上限抬到 8 段 × 60 字（容量 480），长解释因此被拆成更多小段（实测最长单段 170 字）。

### 4.1 读这张表要注意四件事

1. **提问率是环境相关的**：同一实现，t1 的 20 轮口语对话语料是 52.6%
   （`docs/benchmarks/v01-baseline.md` §2.4，旧口径），本语料（含多轮天气问答）主口径约 46%。
   绝对数字只在**同一语料**内比较才有意义——这正是把指标做成「语料驱动的一条命令」的原因。
2. **n=28/次仍然只够看方向**：逐次极差实测 6–7 个百分点（V0.1 这一批三次是 30.3pt），
   别拿单次数字下结论；写结论用「均值（n=3，极差）」。
3. **「禁用模板率 = 0%」不等于没有客服感**：词表只抓字面。V0.1 真正露馅的地方是
   **同一句收尾的反复**（t1 抓到的「了，量完血压」@12,16,19 与「都过十二点了」在这两次运行里
   仍然是重复短语榜前列），以及「每轮一答一补一问」的结构——后者由「最长同结构连续轮」和
   人工抽检覆盖。
4. **`--repeat>1` 时「重复 6 字短语」会被跨次重复污染**（同一句天气问题问 3 次必然重复），
   所以报告里同时给了**逐次的条数**；要判「同一段对话里反复用同一句话收尾」，
   看逐次数字或直接用 `--repeat=1` 跑一次。

### 4.2 顺手量到的格式污染（补充探针，不是指标）

知识类长回答会带 markdown 结构，**朗读时会念出来**。用一条命令从原始记录里数：

```powershell
node -e "for (const f of ['realism-2026-10-01-v01-vanilla.json','realism-2026-10-01-v02-wip.json']) { const j=require('./docs/benchmarks/'+f); const mk=j.rounds.filter(r=>r.reply&&/(\*\*|^\s*[-*]\s|^\s*\d+[.、]\s|^#{1,6}\s|\|)/m.test(r.reply)).length; const em=j.rounds.filter(r=>r.reply&&/[\u{1F300}-\u{1FAFF}\u{2600}-\u{27BF}]/u.test(r.reply)).length; console.log(f, 'markdown='+mk, 'emoji='+em, 'spoken='+j.metrics.spokenTurns); }"
```

实测：A 是 `markdown=2 / emoji=1 / 开口 72`，B 是 `markdown=4 / emoji=0 / 开口 63`（口径改后的分母；见 §2）。
比例低，所以没有升级成正式指标；但 G04 那一轮 473 字的 `**1. 谁欠谁钱**` + 项目符号列表
是真实存在的（A 与 B 都有），语音场景下需要一条「朗读前的格式清洗」策略，属于后续工作
（t7 的 `sanitizeSpokenReply` 处理的是工具标记与外文推理，**不含 markdown/emoji**）。

## 6. 已知局限（写清楚，别当已解决）

- **单次数字不可信**：n=28/次的极差 6–7pt（V0.1 那批三次到 30.3pt）；要下结论至少 `--repeat=3`，并用「均值（n，极差）」写法。
- **词表只抓字面**：pack G07 的「不好」例子（「欢迎回家！今天过得怎么样呀？」）没有任何词级信号，
  语料里显式标成 `detect: 'none'`——只能人工/评审判。
- **G03/G08/G10 未跑**（OpenThread / news 插件 / 打断），G06 只跑第一轮；报告里都写明缺什么。
- **口径缺单测（t17 的 O2）**：「修复句不进分母」「主口径 ≠ 辅口径时按主口径判带」目前没有夹具钉住
  （`tests/scenarios/realism-metrics.test.ts` 未同步），删掉修复句排除也不会红。
- **指标模块的跨包相对导入（t17 的 O3）**：`scripts/lib/realism-metrics.ts` 直接 import
  `../../packages/conversation/src/engine.ts` 取「修复句的唯一定义」；建议后续补一行 re-export 再改回包名导入。
- **B 是脏工作区快照**：见 §4 的说明与报告里的「工作区」一行；权威 after 数字按 §7 重跑。
- **`--fake` 运行不要落在 `docs/benchmarks/` 下**：默认 `--out` 就是那里，会写出没人认领的
  `realism-<日期>-fake.{md,json}`（曾发生过一次，已删除）；自检请加 `--out %TEMP%\<目录>`。
- **工具缺陷（已修，留档；t5 收口时发现）**：用 `--replay <旧 JSON> --re-render` 重写报告时，
  「逐次重复」表的主口径列曾显示 `NaN%`、`重复短语（本次内）`列曾显示 `undefined`——**原因**是旧 JSON 存的
  `perRepeat` 是改口径**之前**的字段，而重放路径只重算合并指标、不重算 `perRepeat`，渲染器按新字段名读。
  **修法（已落地）**：运行时给每一轮记录 `run` 序号；重放时按序号分组重算 `perRepeat`（`groupRepeats`），
  对没有 `run` 序号的老 JSON 回退到「按 scenario 序列重启切分」（每一次重复都从语料第一个场景的第 0 轮开始），
  并把 `run` 序号写回 JSON，下次重放不再靠推断。
  **可核对的修复证据**：同一条命令 `node scripts/eval-realism.ts --replay docs/benchmarks/realism-2026-10-01-v01-vanilla.json --re-render --out docs/benchmarks`
  ——修复前逐次表是 `NaN% / NaN% / NaN%` 与 `undefined`，修复后是 `28% / 58.3% / 52.2%`（n=3，均值 46.2%，极差 30.3pt）
  与 `12 / 3 / 9`；两份报告（`.md`）与两份原始记录（`.json`）现在都查不到 `NaN`/`undefined`。
  **回退切分的已知前提**：它依赖「一次重复从语料第一个场景开始」这一结构；若将来语料改成随机顺序，
  请只依赖 `run` 序号（新写的 JSON 都有）。
- 本文不写死测试项数与耗时（会漂移）；要看门禁结果请自己跑 `npm test`。

## 7. 交接：怎么产出权威的 after 数字

1. 等 P1（t2）与后续在途任务全部 commit、`git status` 干净；
2. 在**同一个语料、同一个模型**下重跑：
   `node scripts/eval-realism.ts --corpus=all --repeat=3 --label v02`；
3. 报告里的「工作区」一行必须是「干净」（否则数字属于快照）；
4. 与本文 §4 的表逐行对比，或直接用
   `node scripts/eval-realism.ts --replay docs/benchmarks/realism-<日期>-<label>.json` 复算；
5. 门禁口径：黄金机械期望必须 0 违规（exit 0），提问率进入 30–50% 带内，
   单段最长不再出现 300+ 字的巨段。
