结论先写，后面才是口径与逐项数字：

1. **承载指标是 ④「首段可听总延迟」**（= 端点保持 + ① + ② + ③）。pack 说的「首音」是
   「说完一句到听见第一个字」，只有 ④ 是这个量。③「首 token → 首段可听」只是**归因量**：
   它说明 ④ 里有多少属于语音合成，不是目标本身，也不能跨链路直接比（一边是「第一块」，
   一边是「整段回复」）。
2. **pack 的 1.5 s 目标未达成**：本批 ④ P50 = 5.2 s，是目标的 **3.5 倍**；
   对照 V0.1 历史基线 ④ P50 6.8 s，本批是它的 **0.77 倍**（−23%）。
3. **同一批、同一公式下的对照确实有改善，但没有质变**：同批 `--legacy-tts`（同一段回复文本上
   再整段合成一次）③ P50 2.06 s → 流式 ③ P50 1.47 s（−28.8%），④ P50 6.01 s → 5.26 s（−12.5%）。
   即：**改造方向有效、幅度不足以改变数量级**，离 1.5 s 差的是模型首 token（② P50 1.76 s，
   单独就已超过目标）与 TTS 单次往返（③ 的地板）。
4. 测量抖动很大：本批 ② 从 464 ms 到 8 609 ms，③ 从 1 201 ms 到 6 327 ms。任何单次运行的
   P50 都只能当同口径对比物，不能当 SLA（与 docs/benchmarks/v01-baseline.md §3.2 的告诫相同）。

## 三、归因：差在哪、什么条件下才够

1. ④ = 端点保持（≈450–680）+ ②（1759）+ ③（1466）。要让 ④ ≤ 1500，②+③ 必须 ≤ ~1000，
   而 **② 单独就接近 1.8 s** —— 那是模型首 token 的延迟，不是语音链路能改的量。
2. ③ 的构成（`--trace` 逐 delta + 直接探针实测）：
   - 首 token → 首块 dispatch：早期版本 0 收益（等整段）→ 现在 60–300 ms（首个安全标点即放行，
     见 `SpeechPipeline` 的 `earlyFirstClause`）；
   - MiMo TTS 单次往返实测（同一进程、同一 key、4 种长度 × 3 轮）：
     2 字 581/870/1050 ms、3 字 711/785/860 ms、13 字 969/1150/1185 ms、30 字 1613/1806/2016 ms。
     即首块 10–16 字 ≈ 1.0–1.3 s，这就是 ③ 的地板。
3. 打中 1.5 s 只有两条路（都不在本轮范围内）：(a) 更快的 TTS（本地或更低延迟的端点）；
   (b) 首块切到 4–6 字（③ ≈ 0.6–0.9 s，代价是听感变碎、总时长与调用数上升）。
   并且**必须同时把 ② 压到 ~600 ms**，否则 ④ 仍到不了 1.5 s —— 换 TTS 也救不了模型首 token。

## 四、打断与应和（离线测量，纯本地、不花钱）

```powershell
npm run voice:bargein                     # exit 0（= node scripts/voice-bargein.ts）
node scripts/voice-bargein.ts --strict    # exit 0，可失败的可听停止判据
```

- **判定延迟 192 ms ≤ 500 ms 目标**（VAD 提交 STARTING/SPEAKING − 真实语音起点），由用户夹具
  与 VAD 决定；
- 播放队列：3 段，已听 992 ms，丢弃 3 段（**5 008 ms** 未播音频）；
- **可听停止判据**（t11 起带反事实证明）：探测点 1950 ms（= 打断点之后下一段音频的起点）——
  打断后仍在播 **否**／未打断时应为 **是**。两条同时成立这条判据才成立，否则判 failed
  （t5 评审证明：只问被打断的时间线时，它在 10 001 个瞬间全部回答「不可听」，判据无法失败）；
- **助手音频固定为 `tests/audio-fixtures/bot-reply-fixture.wav`**（签入的确定性夹具）。以前默认
  读 `data/voice/reply-1.wav`，那是被每次 `npm run voice:turn` 覆写的产物，所以「丢弃了多少毫秒」
  随最后一次回复变化（t5 评审）。判定延迟与它无关，固定它只为让播放数字可复现；
- **可达性（写进 caveat）**：麦克风只在「按住说话」按下期间采样，所以这条规则可达的条件是
  「他正按着按钮、而她又恰好在说话」；没有按键时她说完一句不会被打断。页面上也是这么写的；
- 应和候选：本夹具只有 1 段语音、没有内部停顿（pauseMs 空），决策 = 无 —— 如实报告；
- 仍未验收：扬声器物理静音延迟需要设备验收（§33 的 P50 < 500 ms 不在本证据内）。
