## 7. 观测（都不改变 verdict）

- **O1（低，残留风险，属这类约定的固有边界）**：留档的旧数字（180 / 139 / 209 / 27–30s）仍**出现在正文**，虽然都在「核对当时 / 已过期 / 当时快照」的语境里；一个只搜数字、不看上下文的转抄者仍可能把它们抄走。§0b 已经把它们都点名成「当时快照」，要再硬一档只能在每个旧数字旁边再加一句「勿引用」——收益递减。真正的闸门是 `AGENTS.md` §9.18 + 每份文档的「带日期实测点」约定，文档只能写到这个程度。
- **O2（信息，背书他人收尾需要抽查）**：t94 把 §3 的三条待办标为「都已收尾」，并注明归属（t82 / t84 / t90 / t94）与核对命令——这等于替别人的收尾背书。我抽查了其中一条：`git grep -n "onSegment" -- scripts` 命中 `scripts/chat.ts`，与文字一致 ✓。其余两条（计数口径、conversation.md §6/§7）在 t90/t82/t84 的提交里能对上（本报告 §5 的提交级核对）。
- **O3（低，措辞）**：§0b 里「更早的集成收口实测点是 209 项 / **19.1s**」带了一个耗时数字；耗时与项数一样会漂移，现在靠「更早的」限定，可接受；若想更严格，可写成「209 项 / 19.1s（同为历史值）」。
- **O4（信息，正面：值得当模板）**：§0b 第 45–49 行把「不要做什么 + 为什么 + 怎么做」放在一段里，并在 §2/§3 各复述一次，形成「入口提醒 → 规则复述 → 历史证据仍可查」的三层结构；配合 §5 的核对结果（快照文档未被顺手改动），这次的改造没有制造新的漂移源。建议后续新增文档直接把这五行当模板抄（它已自带日期，抄的时候只需换成当天实测点）。
