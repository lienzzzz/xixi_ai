## 1. 结论

**verdict：needs_revision（1 条 medium + 2 条 low finding）**

一句话：**机制本身是对的，我按验收逐条独立验过——① 无工具 + 具体值→替换、有工具→原样，② 验收点名的那两句家常话不被误伤，③ 主动开口走同一个判据而且 `tool_name` 真的写进了 assistant 轮**（我用 `ProactiveLoop.tickOnce()` 端到端跑出来：未核实→发固定短句、`tool_name=null`；核实过→模型原文、`tool_name=xixi_get_weather`）。**但是「家常话不被误伤」这句作为一类话的说法不成立**：归属规则（`ATTRIBUTION`）只要出现「医生说 / 新闻 / 朋友说 / 专家 / 别人说」这类**来源词**就触发，**不要求句子里有任何可核查的事实**——我端到端跑出 5 句普通家常话被整句替换成「这个我记不准，不敢乱说——要不我查一下再告诉你？」，其中「朋友说要来吃饭」还是**在复述用户自己的信息**（F1，medium）。另外两条小的：三位数温度在审计说明里被**截断成后两位**（「180 度」记成 `80 度`、「100 度」记成 `00 度`，F2，low）；t111 的实测结论「tool=null 的轮次都不含具体值 → 违规 0」作为**台账陈述**不成立——我扫出 **7 条** `tool_name=null` 且含温度值的 assistant 轮（全部早于本次修复），而台账里**没有任何一条**修复后的新轮次（F3，low）。

| 1 独立核对四件事（① 触发条件 ② 家常话不误伤 ③ 主动开口同判据 + tool_name ④ 真密钥实测） | **不通过**：①③ 成立；② 点名例子成立、但**整类不成立**（F1）；④ 本机没有密钥**跑不了**，改用台账重算后发现结论措辞过宽（F3） | §2、§3、§4、§5 |

## 2. ① 检测器只在「无工具 + 查得到才知道的具体值」时触发（我的夹具）

判据来自 `screenUnbackedFacts(text, toolName)`（`respond()` 与主动开口共用）。我自写的 9 个「该拦」夹具**全部拦住且替换成修复句**：`明天成都阴天 19 到 25 度`（`temperature:19 到 25 度`）、`明天降水概率 80%`、`屋里湿度 65，有点潮`、`海上风力 4 级`、`今天空气质量 120`、`紫外线指数 7，注意防晒`、`天气预报说明天有雨`、`气象台说今晚降温`、`新闻里说小区要停水`。

`respond()` 的两条路径（我的假适配器，直接给文本 chunk / 先给 tool chunk）：

| 情形 | 结果 |
|---|---|
| 无工具 + 「明天成都阴天 19 到 25 度，记得带伞。」 | **替换**：`turn.text` = 修复句、流式吐出的就是修复句（`19` 从未到 TTS）、落库的 assistant 轮也是修复句、并发出 `onNotice({code:'UNBACKED_FACT_CLAIM'})` ✓ |
| 先 `{type:'tool', name:'xixi_get_weather'}` 再同一句话 | **原样放行**：`turn.text` = 原文、无通知 ✓ |
| 家常话「今天有点冷，多穿点。」 | 原样放行 ✓ |

## 3. F1（medium）：归属规则会误伤一整类家常话

`ATTRIBUTION = /(?:天气预报|气象台|预报|新闻|报道|专家|医生说|医生|朋友说|别人说|他们(?:说|告诉))/` —— 它匹配的是**来源词本身**，不要求同句里有任何「只有查得到才知道」的内容。我端到端（`respond()`，无工具）跑出来的用户可见结果：

| 模型原文 | 用户实际听到 |
|---|---|
| 今天有点冷，多穿点。 | （原样）✓ |
| 医生说多喝水对身体好，你也多喝点。 | **这个我记不准，不敢乱说——要不我查一下再告诉你？** |
| 今天新闻挺热闹的，说小区门口要办集市。 | **同上（整句被替换）** |
| 朋友说要来吃饭，我先把菜洗上。 | **同上** |
| 专家都觉得这样安排挺好。 | **同上** |
| 你把烤箱预热到 180 度，我这边切菜。 | **同上** |

- 后四句没有一句是「模型编造的查得到的事实」：前两句是一般常识/闲聊，第三句是**复述用户自己说过的信息**，最后一句是用户刚给的**指令**。
- t111 的回报写「检测器只认数值与归属类具体值，**故意不碰**「今天有点冷，多穿点」这类家常话」——**点名的两句确实不碰，但「这类家常话」作为一个类是被误伤的**；而且 `tests/unit/core/unbacked-fact-claims.test.ts` 的负例只钉了三句（`今天有点冷，你多穿点` / `我在想明天要不要出门走走` / `收到：你好`），**没有任何负例覆盖「来源词但无事实主张」这一类**。
- 方向上是「偏安全」，代价却是**答非所问**：用户听到的是一句与上下文无关的「我不敢乱说」。
- requiredFix（二者取一，建议前者）：把归属规则收紧到「**有内容可核查**」的形态——例如只保留 `天气预报/气象台/预报/报道/新闻里说` 且要求同句出现事实元素（数字、引语、`说…了` 的从句），把 `医生/专家/朋友说/别人说/他们告诉` 这类**裸来源词**去掉（它们出现在家常话里的概率远高于出现在编造里）；并为上表 5 句加负例，钉住「家常话不被误伤」这个类级承诺。

**本机没有 `MIMO_API_KEY`，也没有 `.env.local`** → 我**无法**用真实密钥跑这一轮（这是环境限制，不是判它不合格的理由；t111 的「真机两轮」我没法复现，只能核它的产物）。我改用**台账独立重算**：扫 `data/**/*.sqlite` 里所有 `conversation.turn` 事件，用**同一个** `findUnbackedFactClaims()` 判「含查得到才知道的具体值」，再看该轮的 `tool_name`。

| 台账 | 含具体值 & 伴随工具 | 含具体值 & `tool_name=null` | 时间范围 |
|---|---|---|---|
| `data/chat/xixi.sqlite` | 1（13:02，`xixi_get_weather`） | **6**（07:57 ×2、08:16 ×4、08:17） | 07:57–14:31 |
| `data/field-test/xixi.sqlite` | 2（11:12、15:05，均 `xixi_get_weather`） | **1**（11:12:54） | 11:12–17:56 |

- **「4 条全部伴随 `xixi_get_weather`」这句我复现成功**（4 条分布在三个库里，每条都含温度值）✓——这也是为什么只看一个库会漏（我第一次只扫 `data/chat` 时只看到 1 条）。
- **但「tool=null 的轮次都不含具体值 → 违规 0」这句不成立**：台账里有 **7 条** `tool_name=null` 且含温度值的 assistant 轮，例如 `data/chat/xixi.sqlite` 07:57 的「明天下雨，18到25度，出门记得把伞。」——**这正是 t111 要修的那个 bug 的现场**（说明这个 bug 在真机上真的发生过 7 次）。
- 这 7 条的**时间最晚是 15:05，而修复的提交是 19:55** → 它们都是**修复之前**留下的行；同时，**台账里没有任何一条修复之后的新轮次**（我也找不到那「两轮」写入的行）。所以：
  - 作为「**台账整体**」的陈述，「违规 0」是**假的**；
  - 作为「**修复之后**」的陈述，它在台账上**既不能证实也不能推翻**（没有样本），只能由 t111 自己的运行窗口/我这次的离线探针来支撑。
- requiredFix（纯文字，不用改代码）：把结论限定成事实——「修复**落地后**的轮次里 4 条含具体值的都伴随 `xixi_get_weather`；**台账历史里仍有 7 条修复前的编造轮次**（最晚 15:05），它们不会被追溯修改」；并把这几个数写进 `docs/progress.md` / 交接文档时带上扫描命令（`node data/rev-tmp/t114-invariant.mjs` 就是我的扫描脚本，可直接复现；或写成一条 `git grep`/`sqlite` 查询）。

## 6. F2（low）：三位数温度在审计说明里被截断

`TEMPERATURE_SINGLE/RANGE` 用 `\d{1,2}`，所以三位数只会匹配到**后两位**，`onNotice` 里的 `match` 于是不是模型原话：

```
水开了是 100 度        →  temperature:"00 度"
把烤箱预热到 180 度    →  temperature:"80 度"
```

拦下来这件事本身是安全的（这三句都会被替换），但**审计说明记的不是原话**，事后按 `match` 复核会对不上；顺带说明「烤箱 180 度」「100 度」这类**生活常识句**也会被拦（与 F1 同源：判据只看数字+单位，不看语境）。
requiredFix：把量词放宽到 `\d{1,3}`（或 `\d+`）并保持范围分支优先，让 `match` 与原话一致；顺手给「180 度 / 100 度」加两条用例（期望：`match` 完整，或按 F1 的取舍决定是否放行）。
