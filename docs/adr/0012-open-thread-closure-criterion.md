# ADR-0012：未完话题的收口判据（内容字门槛 + 宁可再问一次）

- 状态：已采纳（2026-10-01）；**判据待升级**——本轮是「字」级，下一轮计划升到「词/对象」级（见「已知残余」与「下一轮」）
- 相关：铁律 4、pack §9 与 §10（TopicEngine / OpenThread）、[ADR-0011](0011-proactive-decision-ownership.md)、`docs/progress.md` §2.19、`docs/design/conversation.md`

## 背景

第四轮 t3 落地「第二天追问」（`OpenThreadStore` + `TopicEngine`）之后，t7 评审查到一处会**永久丢事**的缺陷：
`reconcile` 把追问之后的**第一条**用户轮次无条件当成回答，于是用户随口聊一句天气就会把话题静默收口。
实测：话题「明天我要去买药。」下，用户答「今天天气不错啊。」→ 话题判 `engaged`、次日候选为 0，真正的追问再也不会发生。
同类问题还有一处：弱证据路径用**未过滤**的字表比字，「我今天没去散步。」这类也会被 `snoozed`（同样是终态）。

## 决策

1. **收口必须与被问的那件事挂钩**：只有回答里出现话题的**内容字**才收口。内容字 = `subject` 去掉时间词、人称/虚词、位移字后剩下的字
   （「去镇上办证」→ 镇/办/证）——t8 把判据收紧成**一条规则**，并把收紧后与主规则等价的弱证据分支**整段删除**（不留死代码）。
2. **对不上的轮次不动状态**：记进 `ReconcileResult.ignored`——**不写事件、不改状态**，话题保持 `offered`。
3. **宁可再问一次**：由既有的 `reofferAfterMinutes` / `maxAttempts` / `expireAt` 在窗口内把它放回候选——
   不新增机制，也不会没完没了地问（问满 2 次照旧 `exhausted`）。
4. **不用 `snoozed`**：它属已收口状态（`OPEN_THREAD_SETTLED_STATUSES`），会**永久**关掉话题，与第 3 条冲突。
5. **扫描范围含 `candidate + lastOfferedAt`**：回到候选、还没被再问之前他就答了那件事时，不该再问第二遍；
   前置条件严格（仅 `lastOfferedAt` 非空且轮次严格晚于它），不新增状态或写路径。

## 代价（已测量，不是估计）

| 项 | 数字 |
|---|---|
| 收益：无关句被误判为回答 | 13 句探针 **6/13 → 0/13**（换主题「复诊」「理发」0/13） |
| 代价：真答案被漏判 | 9 句真答案探针 **7/9 → 6/9**，唯一新增漏判是「没去成，改天再说吧。」（改为窗口内可再问） |

**取舍理由**：多问一次是**有界、可见**的（还要过主动引擎的硬底线与社会预算），静默丢一件事是**无界**的。

## 已知残余（如实记，不在本轮修）

判据是**字**级：共享**内容字**仍会误收口——不只是通用动词（买/看/吃/拿），**常见名词**同样中招：

- 「明天我要去买药。」+「我去楼下买了点水果。」→ 该主题 **1/13**
- 「明天我要去看孙子。」+「老李家的孙子回来了。」→ 同样 **1/13**

这两类行为被钉成一条**显式标注「已知残余，不是期望行为，修好它必须改这条」**的用例（标签在用例名、用例注释、代码注释三处）。
