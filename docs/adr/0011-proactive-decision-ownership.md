# ADR-0011：主动开口的决定权归谁（硬底线 + 模型读空气）

- 状态：已采纳（2026-10-01）
- 相关：铁律 3、[ADR-0009](0009-proactive-triggers-and-hard-gates.md)、`xixi_v02_refactor_pack` Phase 5、`docs/design/conversation.md`

## 背景

铁律 3 原文是：

> 主动行为必须先过确定性硬门禁（静默时段 / 冷却 / 当日额度 / 重复话题 / 对话冲突 / 置信度），LLM 不能绕过。

这套实现（ADR-0009）把十个分量等权平均成一个分数，再与阈值比较：**单一阈值一票否决**。实测后果是
「不像住在家里的熟人」——主动开口被固定冷却与阈值压成定时播报，话题只能来自很薄的来源
（在场 / 长时间安静 / 时间钩子 / 上一条用户发言），**没有「读空气」**。

`xixi_v02_refactor_pack` 的 Phase 5 指出：**高主动性 != 高频打扰**，应当把「要不要说」拆成
话题质量分、社会预算、读空气（receptivity）、未回应惩罚、话题重复惩罚等**多个可解释的信号**，
而不是一个阈值；并允许「正在热聊时可以连续接话，不受新会话冷却限制」。

用户 2026-10-01 明确指示：社会预算 / 读空气 / 未回应惩罚 / 话题质量分按该包来做，
并且 **「模型可以决定要不要说话」**。

## 决定

主动行为分两层：

1. **硬底线（程序判定，模型不可绕过）**：静默时段、当日额度与 6 小时额度（**次数上限，作为费用代理**）、
   隐私与同意。这些是**不可协商**的边界——它们是安全与成本约束，不是「语气」问题。
   **尚未实现、不得写成已实现**：**金额级的费用上限**（现在只有次数额度）。t4 的独立验证（F6）抓到
   本文早期版本把「费用上限」写成既有硬底线，而全库没有 cost cap——此处已更正；要加就单开任务。
2. **硬底线之外，是否开口由模型读空气决定**：确定性评分只提供**候选与依据**
   （话题质量分 / 社会预算 / 读空气 / 未回应惩罚 / 话题重复惩罚），**不再由单一阈值一票否决**。
   模型可以说「不说」；这个选择与理由同样要落库。

铁律 5 不变：**不存模型私有推理**，只存 `reason_code` 与分数。因此「模型决定」的可审计形式是
——决策记录里带上候选的分数、模型给出的 `reason_code`，以及它是「说了」还是「选择不说」。

### 决定 2 的补充：连续未回应之后是**显著降频**，不是硬停（2026-10-01，第五轮 t1 拍定）

**口径已定**：`xixi_v02_refactor_pack` 的 Phase 5 验收原文写「连续两次主动没人回应后继续主动 = 0」，
本仓库**不采纳那条更严的写法**，采纳的是 pack `02_IMPLEMENTATION_STEPS.md` 的表述——
「连续两次主动没人回应后**显著降频**」。

理由三条，按分量排序：

1. **尖峰与用户意图相反**。用户 2026-10-01 的诉求是「主动性**高一些**、像人」。「= 0」意味着两次
   没人搭话之后**当天再也不开口**——那正是用户抱怨的「主动性远低于预期」的极端版本，
   与本次改造的出发点冲突。
2. **硬停与本文 §决定 的两层设计冲突**。硬底线只该是**安全与成本**边界（静默时段、次数额度、
   隐私与同意，见 §决定 1）；「连续两次没人回应」是一个**质量信号**，不是安全边界。把它升级成
   一票否决，等于把「读空气」又变回确定性门禁，退回本 ADR 要修的那个毛病（单一阈值一票否决）。
   同理，热聊接话（`conversation_continuation`）**不受**这条惩罚——两个人正说着话时「没人回应」
   这个前提本身就不成立（引擎的 `isHotChat`，t9 F5）。
3. **「显著降频」可测且已经测得出来**。判据是一个**幅度**，不是一次布尔判定：
   - 单日口径（pack Phase 5 的 12 小时时间线）：被忽视的一天开口数 ≤ 被回应的一天的一半（实测 **11 → 5，降 54.5%**）；
   - 多日口径（同脚本、只差这条惩罚的反事实对照）：`unanswered_penalty` 0.45 与 0 两次跑，同一自然日的开口数之差
     最明显处 ≥25%，且 **第 3 天仍要开口**（证明它只是降频、不是熄灭）；实测惩罚开 23 次 vs 置 0 28 次（逐日 6/8/8 vs 7/8/12），
     「这条惩罚独自把『说』改成『不说』」的判定 726 次 vs 0 次。
   命令：`node scripts/eval-proactive-timeline.ts` 的 M1–M6 判定表（不回退成硬停那条更严的写法）。

**这条口径落在哪**：`recent_unanswered_penalty` 是加权扣分信号（`unanswered_penalty` 0.45，
权重 0.35），按「最近 3 条里未回应的比例 + 连续未回应的阶梯」两段算（`unansweredGrade`，
t9 F2 修掉了饱和）。信号可以叠加到很高，但**永远不构成禁止**——候选分数够高时她仍然会开口，
而那正是「强候选（时钟钩子、未完话题）扛得住惩罚」这条既有设计选择。

**代价（必须诚实记录）**：这条口径**不保证**「两次未回应后一定不开口」，只保证**整体显著降频**。
所以文档与验收**不得**写成「pack Phase 5 的『= 0』达标」——那句话今天不成立，成立的是
「按显著降频口径达标」。要改成硬停就得重开一次口径（并说明为什么用户意图变了）。

## 后果

- **正面**：主动行为从「定时播报」变成「有理由、会读空气」；用户可以要求更主动而不必担心被骚扰；
  热聊中可以连续接话（不再被新会话冷却卡住）；每个决定都有分数与理由可复核。
- **代价（必须诚实记录）**：
  - 主动性不再由单一阈值保证「频率上限」，**行为更依赖模型判断**，因此**必须**保留硬底线，
    否则静默时段与费用会失守；
  - 需要新的验收方式：**多日**时间线模拟（主动次数区间、generic 话题占比、未回应后降频的**幅度**、
    跨天未完话题是否仍被追问、无骚扰边界、接受率），而不是「阈值 0.495 是否生效」；
    命令是 `node scripts/eval-proactive-timeline.ts`（单日 = pack Phase 5 的五项目标，
    多日 = 本 ADR §决定 2 补充里的 M1–M6 判据）；
  - 「读空气」的质量取决于候选质量——**没有未聊完话题与记忆时，话题质量分只能在薄来源上打分**
    （P3/P4 之后才会真正变好）。
  - 「显著降频」是**幅度**口径：它允许强候选（时钟钩子、未完话题）在连续被忽视时仍然开口，
    所以**不能**把它读成「两次未回应之后一定不开口」（§决定 2 的补充）。

## 备选方案

1. **保持单一阈值一票否决**（原状）：可控、可测，但用户实测「远低于预期」，主动性像定时播报。
2. **全部交给模型决定**（含静默时段与额度）：最像人，但**静默时段与费用会失守**，且违反铁律 1
   （规则与边界由程序负责）——**不采纳**。
3. **两层（本决定）**：硬底线仍由程序判定，硬底线之上由模型读空气——同时满足「像人」与「不失守」。
