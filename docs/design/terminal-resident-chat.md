# S2：终端聊天接入家庭宿主

最后更新：2026-10-05。依据 [整体目标](companion-target-architecture.md) S2，用户已授权自主设计/执行；当前阶段只接一个实际入口。

## 行为与边界

`npm run chat` 的直连MiMo与 `--fake` 分支使用 AmbientRuntime，复用同一对话、长期记忆、权限、审批和提醒表。终端文字输出是一个真实软件端点；打印成功后明确确认 playback complete，不能冒充扬声器验收。保留原有分段与间隔，静默跨进程保持。终端没有身份识别：默认主人公开上下文/无写权限，`/alone` 或显式 `--private` 声明当前独处，`/public` 撤回；每次主人主动输入才刷新这份人工声明，在空闲时60秒TTL照常过期，不由定时器虚构新证据。访客输入使用 `/guest 文本`，不改变主人记忆。

命令：`/quiet`、`/resume`、`/state`、`/prompt`、`/reminders`、`/approvals`、`/approve id`、`/deny id`、`/ack id`、`/tick`、`/exit`。只有当前身份的明确文本命令能改变宿主状态；待批只有一条时「可以/好/不用」可确认/拒绝，同样走程序审批，不把模型判断当用户授权。有多条待批要求指明，不能随便选择一条。普通聊天和访客不能借自然语言覆写身份。

定时tick由同一Node进程产生，15秒一次，不启动额外后台服务。手动 `/tick` 用于可重复调试；不对真实时钟提供 `/advance`。全部输入和tick在入口顺序执行，保证注入事件时钟不被并发动作改变；已有dispatch仍做schema/CAS/去重/权限。每次回复先落queued，写完所有段才标completed；输出失败或API失败留下中断状态，没有工具成功则不能伪造成功确认。命令结果与用户聊天文案分开，未完成提醒/审批可列出。

`--data-dir`、`--profile` 提供显式配置，默认仍使用canonical household store与已验证的端点档案。测试只使用临时库。迁移后工作会话映射属于宿主，长期记忆沿用同一库；不随便把不明身份的旧会话导入私人历史。配置的camera/microphone标识只用于人工事件映射，不打开设备。`--fake` 不读取密钥或联网，离线天气来源继续注入同一registry；API客户端可注入，用真实HTTP替身验证工具循环与失败。

读空气通过StructuredInferenceProvider，在既有主动硬门禁之后请求；请求失败或形状无效选择不说，原因码落审计。忙碌/媒体/隐私由宿主传场景，模型不能绕边界。主动内容本阶段使用真实候选事实对应的安全短句，不能宣称模型内容生成已接线。API指标/预算/模型驱动丰富话题属于S3/S4后续任务。

DSH分支保持现有会话与工具实现：尚不能证明其工具经过此宿主registry，因此不接入新宿主，也不声称其具备统一审批与提醒投递保障。其他三个live入口不改。不会为了“全接线”的文案绕过Harness边界。

## 自动验收

真实文件库＋注入时钟/Provider验证：独处/公开权限、主人/访客记忆、真实审批创建/冻结/批准/重启、静默恢复、提醒完成/确认、API工具成功/工具失败/断网、只在打印完成标delivered。真实CLI子进程用fake验证命令、重启与配置，并保留旧language/personality/import/wiring测试。

不验证真人体验、真实API供应商、物理音频、断电或三个其他入口。本阶段完成须默认全量测试与demo通过、文档同步，再进入S3。
