# S3第四步：有界旧原话检索

最后更新：2026-10-05。性质：实施设计；针对临时话题滑出短历史的连续性缺口。

## 选择

本步采用同一私人会话中有界检索旧用户原话，而非生成式摘要。最多读取最近200条主人用户消息、返回2条完整原话，总注入最多2048 UTF-8字节；过大原话整条跳过，不剪裁。复用已有字词相关性函数，纯词面匹配存在召回局限，不称为语义理解。没有内容锚点的「继续那个」不能保证找回。

旧原话以JSON引用数据和时间进入user动态块，明确只是历史陈述，不代表现在事实/授权，不进入system稳定前缀，不当新指令。候选排除当前和短历史事件；不读其他会话/访客/助手原话，公开或禁用context时不召回。来源会话截止在读取时生效，不保存检索缓存，记忆纠正/删除与重启失效保证沿用第三步。

当前输入和硬政策仍受既有预算保护；旧原话块可按完整行淘汰。配置 `context.history_recall.enabled` 可关闭，缺省开启但仍要求私人context。无新依赖/迁移、模型调用或永久记忆提取；不声称真实真人感提升，也不是完整摘要方案。

## 验收

先红验证实际引擎十余轮后相关原話滑出history且没被找回；实现后验证旧话题召回、当前不重复、公开/跨会话不注入、删除截止和文件库重启、整条字节预算。离线demo和类型/全量/文档/独立评审先过，再进入下一软件块。
