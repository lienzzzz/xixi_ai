# S4第一步：软件宿主输入反压

最后更新：2026-10-05。性质：实施设计。S3软件回归/demo已过，真实API体验验收仍待外部验证，本步顺序完善常驻资源边界。

## 当前缺口与取舍

AmbientRuntime与TerminalCompanion各用无限Promise链，慢模型/播放时可无限保存待处理输入。采用共享有界FIFO队列，容量包括执行中的任务，默认64，可通过宿主构造参数maxPendingEvents配置1至1024；满队列在接纳、复制事件和落库前明确拒绝INPUT_BACKPRESSURE，不静默丢消息、不重排已接纳任务、不自动重试。生产者保留未接纳用户输入，等待空间后决定是否重送；拒绝不代表动作执行失败，因为尚未进入执行。

运行时在复制入队前校验事件形状，终端入队前拒绝超过4096字符的输入；运行时4000字符speech契约不变。容量只约束单宿主pending输入，终端和运行时分别防护；不称为整体RSS上限、API并发额度或硬件吞吐保证。FIFO期间静默/中断命令同样排队，本步不引入抢占策略。

任务成功或失败均释放槽位；close拒绝新接纳并等待已接纳任务，错误不毒化后续队列。队列本身仅内存，持久claim/重启去重保持原机制，未接纳任务不落claim。无依赖/迁移，不压缩输入/输出账本，不解决异步外部动作fencing。

## 验收

先红验证慢任务占满容量后第三任务拒绝、不会执行/落库、成功/失败释放、FIFO和关闭等待。实际AmbientRuntime/TerminalCompanion离线慢模型验证，两处容量均生效。新增可运行demo，类型/全量/文档/只读评审后再做下一S4软件块。
