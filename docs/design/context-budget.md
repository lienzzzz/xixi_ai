# S3第一步：上下文预算与稳定前缀

最后更新：2026-10-05。性质：实施设计，完成证据见progress；S3整体尚未完成。

## 范围与取舍

沿用短历史和每轮重新检索的长期记忆，增加确定性的UTF-8文本预算。扩大历史窗口会扩大API输入；生成式滚动摘要需要新的持久化、来源和纠正失效机制；本步采用有界原文历史，不引入摘要或新依赖。长期记忆依旧从当前有效记录检索，纠正/撤销不复用旧检索结果。未解决长窗口外的临时话题连续性。

稳定system只含身份、硬政策、有效人格与自我设定；心情和听众移入当前情境。程序权限不变。历史按事件ID排除本次刚落库的用户轮次，不能按文本去重，否则会误删用户重复说的话。

context.budget可配置max_prompt_bytes（默认32768，范围8192至131072）、max_history_bytes（默认8192，范围0至65536）。它只约束system/history/user三段UTF-8文本，不等于token、HTTP请求、工具定义/结果、图片或金额预算。无法容纳硬政策及完整当前输入时，在调用模型之前明确失败，不能截断用户话语或安全条款。

淘汰顺序：先清除最旧历史，剩余历史为连续后缀，按角色保留完整消息；再从关系、未完话题、记忆块末尾减少完整行。不切半句、不把被删上下文伪装成摘要。必要情境、听众、心情和当前输入必须保留。诊断包含schemaVersion、文本字节/淘汰计数及system摘要，不含原文；这是前缀稳定证据，不是供应商缓存命中证据。

超预算抛带code的错误，已接纳的失败轮次仍由conversation.decision记录accepted/SILENCE与分数；system.health附schemaVersion=1及CONTEXT_BUDGET_EXCEEDED原因码，不附原文或模型推理。私人/公开模式context层是否启用不同，system可能不同；同一分区与人格版本内部才比较前缀。

## 验收

先观察重复当前轮次、前缀随场景漂移及超预算的红灯，再接真实ConversationEngine和终端宿主。离线长会话demo在临时数据库进行多轮文字、重开宿主、私人偏好纠正/撤销和访客切换，输出结构化报告。门禁顺序为类型、全量离线测试、demo、文档检查。真实供应商cachedTokens、同语料真人感对比与长窗口摘要仍是后续S3任务；不宣称本步已证明模型效果或缓存收益。
