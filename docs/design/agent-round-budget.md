# S3第二步：工具循环预算与用量可观测性

最后更新：2026-10-05。实施设计；S3整体未完成，持续软件优化授权有效。

## 当前问题

S3第一步仅限制system/history/user文本。工具定义、assistant工具调用参数和tool结果可能继续扩大下一轮。供应商usage已在客户端解析，但经过BrainAdapter和ConversationEngine时未交付到宿主。

## 实现边界

每轮模型调用前检查messages与tools的JSON数据字节，默认65536、可配置8192至1048576。这是BrainAdapter输入的数据预算，不是完整HTTP报文、token或金额预算。包含附在MimoMessage上的图片base64；不剪裁任何参数、工具结果或用户输入，超限明确拒绝下一轮。模型给出的大工具调用批次在执行前检查，避免超限批次发生外部动作；工具执行后结果超限时停止后续模型调用，保留真实工具执行记录，不自动重试。工具结果不能截断成看似成功的半个JSON。

ToolRegistry给出的模型工具列表按名字排序，参数对象键递归确定性排序、数组顺序不改；注册权限、scope、回合上限不变。模型和schema仍可替换。

MiMo客户端明确区分usage/cached_tokens是否实际返回。每轮完成后聚合到BrainTurnResult并传到ConversationTurn，schemaVersion=1，仅计数及完整/部分/不可用状态，无原文。fake/DSH未知用量不假装成真实0 token。真实供应商缓存未验证，离线HTTP/SSE返回值只是接线证明。

## 验收与后续

先写初始超限零模型调用、大参数批次零写操作、巨大工具结果只调用一轮、不重复执行、工具顺序稳定、SSE多轮usage聚合与缺失unknown探针。接实际终端配置和健康原因码，超限失败仍决策审计；新增离线demo。类型、默认全量、demo、文档、独立评审通过后继续S3长窗口连续性和原文删除传播。无新依赖/迁移，无真实API或硬件。
