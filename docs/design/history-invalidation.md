# S3第三步：记忆变更与聊天历史失效

最后更新：2026-10-05。性质：实施设计，本步只解决有来源事件的语义/情景记忆与工作历史传播。

## 问题和选择

有效记忆检索已过滤撤销记录，但ConversationEngine仍用recentTurns获取旧原文。仅删除来源用户句不能防止助手复述和后续引用；删除审计事件则混淆事实与工作上下文。因此新增每会话持久截止序号：有来源的记忆内容编辑、删除或状态变更，在同一事务中把来源会话截至当时的全部历史排除出后续模型工作上下文。牺牲该会话的一小段临时连续性，换取可验证的旧原文失效；有效长期记忆仍每轮重新检索。

原始recentTurns和Raw Event不改写，新增recentContextTurns只返回截止之后的完整消息。当前新输入仍按事件ID去重，其他会话不清空。迁移010新增schemaVersion=1截止表，不存原文、模型推理或金额；已发布迁移不修改。删除记忆后截止仍在，重启不恢复旧上下文。事务失败同时回滚记忆与截止。

来源为null、不存在或没有会话时无法定位，不清空整个家庭历史。这不等于彻底擦除原始事件、其他派生记录、供应商保存或旧Harness会话；DSH已有服务端历史需另行设计失效。本步覆盖ConversationEngine组装的本地工作上下文，尚无生成摘要。

## 验收

先红验证语义撤销/编辑/删除和情景编辑/删除传播；文件库重启、原始审计仍在、其他会话不受影响、新输入保留、真实引擎prompt不带旧复述。类型→全量→离线demo→文档→独立评审。当前工具预算步通过评审后才写本步生产代码。
